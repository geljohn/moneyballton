# Project Decision Log

| Decision | Why? | Alternative Considered | Risk |
| :--- | :--- | :--- | :--- |
| **Rolling Historical Cohorts** | Simulates repeated annual scouting decisions while preserving temporal integrity and allowing out-of-sample validation. | Single blended historical pool | Limited sample size reduces statistical power across macro shifts in football environments. |
| **U23 Age Cutoff** | Provides a 3–5 year development runway to evaluate post-identification trajectories. | U21 cutoff | Excludes late-blooming prospects who break through after 21. |
| **1,200 Senior Minutes Filter** | Dampens extreme small-sample per-90 rate spikes while retaining high-upside rotation talent. | 900 minutes or 2,000 minutes | 900 mins introduces high variance; 2,000 mins filters out emerging rotation talent. |
| **Development Leagues Scope** | Captures emerging talent in primary feeder environments (Eredivisie, Championship, Primeira Liga). | Strictly Big 5 leagues | Biases pool toward already expensive, established targets outside recruitment profile. |
| **Relational Database (MySQL)** | Enforces schema discipline, separates cohort discovery from outcome tracking, and demonstrates ELT pipeline design. | Flat local CSVs | Increases local development dependencies and setup overhead. |
| **Tactical Role Definition First** | Prevents overfitting to personal stylistic quirks of an individual player rather than team requirements. | Pure unsupervised EDA clustering | May bias metric weights toward qualitative tactical assumptions rather than data. |
| **Browser-Based Extraction** | Standard HTTP extraction encountered access restrictions, requiring a browser-based driver for historical data ingestion. | Standard requests / urllib scraping | Perceived as fragile if not documented clearly as an infrastructure constraint. |
| **Allowing Overlapping Cohorts** | Simulates multi-year club scouting cycles without violating the temporal firewall (zero future leakage). | Restricting players to a single historical appearance | Fails to reflect how clubs monitor developing assets across consecutive windows. |
| **Rephrased Project Claim** | Clarifies that the model predicts establishment for a specific tactical role, rather than trying to match a specific player clone. | "Predicting the next star" | Methodologically indefensible; sets an unprovable standard of success. |
| **The "Freeze" Protocol** | Enforces strict separation between Discovery (scoring) and Outcome (evaluation) datasets. | Iterative tweaking after observing outcomes | Hindsight bias and curve-fitting, destroying model validity. |
| **Deprecating Possession Metrics** | Upstream extraction constraints prevented uniform collection of player-level carry/take-on metrics. | Writing custom web scrapers from scratch | Significant time investment with ongoing risk of rate-limiting/IP blocking. |
| **Analyst-Defined Weights (Stage 3)** | Deliberately heuristic rather than statistically learned to maximize interpretability for non-technical stakeholders. | Black-box ML regression (e.g., Random Forest) | High risk of overfitting on smaller football datasets; opaque to football directors. |
| **Defensive SQL Engineering** | SQL `CASE` fallback handles missing upstream API league strings without dropping records or breaking the pipeline. | Allowing queries to fail on null/empty strings | Silent data loss where elite prospects are dropped from shortlists. |
| **Modelling Assumption (Fallback = 0.80)** | Assigns a conservative 0.80 multiplier to unmapped leagues to retain records for manual qualitative review. | Assigning a NULL score | Subjective penalty that may introduce bias if unmapped league is elite. |
| **Three-Tier Recruitment Stratification** | Raw scores ignore market mechanics; stratifies output into actionable tiers (Elite, Development, Rotation). | Presenting an unadjusted 1–15 ranked list | Stakeholders dismiss model as impractical if it naively recommends untouchable superstars. |
| **Dedicated Table (`fbref_raw_2526`)** | Isolates current live scouting data from frozen historical validation cohorts (`fbref_raw_2018_2024`). | Appending live data directly to historical tables | Risk of accidental schema drift, accidental table overwrites, or data leakage. |
